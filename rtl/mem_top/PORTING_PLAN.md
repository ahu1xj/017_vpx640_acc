# mem_top 验证与 DMA 学习计划

## 思路

**用一个"假 DDR"把 `mem_top` 单独围起来测，顺便学懂 DMA。**

```
┌─────────────────────────────────────────────┐
│  mem_top_tb                                  │
│                                              │
│   cmd_gen ──CMD2命令──> ┌───────────────┐    │
│                         │ dma_axi4_master│ ← 被测
│   比对器  <──读回数据── └───────┬───────┘    │
│                                 │ m_axi(AXI4)│
│                         ┌───────↓───────┐    │
│                         │ axi4_slave_mem │ ← 你写的"假 DDR"
│                         └───────────────┘    │
└─────────────────────────────────────────────┘
   ↑ 这里往上：你要验证的
                    ↑ 这里往下：MIG + 真 DDR，默认是对的
```

**信任边界**：MIG ↔ DDR 的物理通路由厂商 IP 保证（`vivado/mig_ex/.../sim_tb_top.v` 已测过，是 `docs/VERIFY.md` 的 P2 关卡）。我们只验证 `mem_top` 产生的 AXI4 访问是否合规。

**`axi4_slave_mem` 不只是存储器，更是协议断言器**——它要抓住 `mem_top` 的违规：

| 检查项 | 违反后果 |
|---|---|
| 突发不跨 4KB | AXI 硬性要求，真机会挂 |
| `awlen/arlen` ≤ 上限 | 超限真机会拒绝 |
| `awsize` 与位宽参数一致 | 不一致会错位 |
| `wlast/rlast` 位置正确 | 错位会截断/串包 |
| `wstrb` 合法、响应码正确 | —— |

## 为什么这么做

| 收益 | 说明 |
|---|---|
| **迭代快** | 单元 tb 一轮几秒；chip_tb 要等 SRIO 链路训练，一轮几十分钟 |
| **敢改代码** | 后面要参数化 `dma_cmd_splitter`（地址算术），没有单元 tb 不敢动 |
| **换板后仍成立** | 验证的是 `mem_top` + **AXI4 接口**——换板换的是 AXI4 对面那个东西，接口不变 |
| **一箭双雕** | 同一个 tb 既是回归工具，也是学 DMA 的实验台 |

## 交付物

```
tb/mem_top/
    axi4_slave_mem.v     AXI4 从机 + 存储 + 协议断言器（参数化）
    mem_top_tb.v         cmd_gen + 比对器 + 用例
    cases.md             用例清单
```

**`axi4_slave_mem` 参数**：

| 参数 | 取值 | 用途 |
|---|---|---|
| `AXI_DATA_WIDTH` | 64/128/256/512 | 四档都要能跑 |
| `ADDR_WIDTH` | 32 | —— |
| `MEM_DEPTH` | 可配 | —— |
| `READY_DELAY` | 0 / 随机 / 固定 N 拍 | 模拟不同 DDR 延迟 → 测 FIFO 深度 |

## 任务

| # | 任务 | 验收 |
|---|---|---|
| **T1** | 写 `axi4_slave_mem.v`（含 6 项协议检查）| 自带自检用例通过 |

| **T3** | 基线与用例矩阵 | 见下 |
| **T4** | **DMA 实验**（学 DMA 的实操部分）| 4 组实验都跑过、现象有解释 |
| **T5** | 结论回填 | FIFO 深度建议 + DMA 笔记 |

### T3 用例矩阵

| 维度 | 取值 |
|---|---|
| 位宽 | 64 / 128 / 256 / 512 |
| 长度 | 1 拍 / 4KB±1 / 最大（256 拍突发）|
| 地址 | 对齐 / 非对齐 / 跨 4KB |
| 模式 | 单笔 / 背靠背 / 读写交错 |
| 延迟 | `READY_DELAY` = 0 / 大值 |

### T4 DMA 实验（四组）

| 实验 | 操作 | 学什么 |
|---|---|---|
| ① 拆包 | `AXI_DATA_WIDTH` 512→128 | `BEATS_PER_APP` 1→4，看拆包顺序 |
| ② 突发切分 | 发一条跨 4KB 的命令 | `dma_cmd_splitter` 怎么切、为什么 |
| ③ 突发上限 | 改 `MAX_BURST_BEATS` 256→16 | 突发数变多、描述符节奏变化 |
| ④ 反压 | `READY_DELAY` 调大 | FIFO 占用峰值 → **决定要不要调 `dma_axi4_master.v:11-17` 的 7 个深度** |

### T5 的 DMA 自测题

1. "写 8KB 到 0x1000" 会变成几条 AXI 突发？为什么是这个数？
2. 4KB 边界为什么必须切？不切会怎样？
3. 突发上限为什么是 256？改成 64 影响什么？
4. `AXI_DATA_WIDTH` 从 512 改 128，什么变了、什么没变？
5. `m_axi_awready` 长期拉低时，`s_axis_wrddr_tready` 会怎样？为什么？
6. 编译期防错用"例化不存在的模块"（`dma_write_driver.v:321`）——为什么比 `$error` 好？

## 与移植的关系

```
本计划（单元验证 + 学 DMA）
        ↓
参数化 dma_cmd_splitter（有了 tb 才敢改）
        ↓
换板对比仿真（基线 A：现有 MIG+DDR3模型 / 基线 B：新板 MIG+新 DDR 模型）
        ↓
新 top + 上板
```

**换板对比仿真**是下一步：同一份激励分别在两套 DDR/MIG 上跑，比**功能结果**与**AXI 访问序列**（两者必须一致），时序差异允许但要解释。

## 非目标

- ❌ 不自研 DDR 控制器（PHY 训练是板级物理问题，用 IP）
- ❌ 不改 `cnn_acc_top` 及以下的接口
- ❌ 不追求覆盖 cal_top 的功能（那是 chip_tb 的事）
